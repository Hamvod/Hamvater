# Hamvater outcomes

- [x] **Height and weight profile** — Users enter height and weight, choose supported height/weight units, and receive validation: height is 100–240 cm (3.3–7.9 ft) and weight is 25–300 kg (55–661 lb). For valid values, show the entered profile and update both the male and female model: height scales proportionally to height, and weight-derived BMI adjusts approximate body width/depth. The values remain estimates, are not a body scan, and are not saved.
- [x] **Male and female model selection** — Provide distinct full-body adult male and female fitting models, inspired by the user's linked front-view male figure and interactive female 3D scene. Keep the choices explicit and switchable. Do not include anatomy or model assets copied from the referenced sources.
- [x] **Higher-fidelity model stage** — Show the selected full-body fitting avatar at the centre of a large, clean 3D viewport, with a neutral modest base garment, adjustable profile scale, inspect/turn interaction, and a restrained idle motion. Keep body/model behavior a visual approximation from height and weight rather than implying a body scan.
- [x] **Separated, minimal controls** — Reduce visual clutter and remove unrelated promotional/header content from the fitting workspace. Keep profile/model choices in a distinct left rail and garment/scan/fit controls in a distinct right rail; give the 3D model the primary canvas. At small screen widths, keep the model first and stack both rails below without hiding or crowding the model.
- [x] **Dress capture and upload** — Users can capture or upload a dress image for scanning. The flow includes guidance for framing, lighting, background, and full-garment visibility. Automatically attempt local removal of a uniform plain background for the model layer, including uniform light, dark, or colored edge backgrounds; retain an explicit control to restore the original layer when removal harms garment fabric, and clearly report when a varied background is skipped. Keep the original scan image intact for calibrated size measurement and Compare.
- [x] **Linked measurement engine** — Integrate `https://github.com/xcapt0/object_size_detector` for object and garment size estimation where compatible, preserving the requested engine rather than substituting another implementation. Make the detector's requirements and assumptions visible.
- [x] **Scan readiness and feedback** — Check whether a scan contains the required reference object, usable camera/image quality, and calibration assumptions imposed by the linked engine. Explain incompatible or unmeasurable scans and invite a retake; do not fabricate calibrated measurements. Ignore any in-flight scan response if another upload/camera capture or a restart has changed the active image; never apply old measurements or crop bounds to the new garment.
- [x] **Garment-on-avatar preview** — Place the submitted garment as a controllable overlay on the avatar, scaling it to create an animated visual try-on preview based on measured garment dimensions when available and the user's basic measurements. When calibrated contour bounds are available, crop the fitting layer to the garment area so the separate reference marker is not shown as clothing; retain the full original scan for comparison. Keep uncalibrated previews visibly marked as approximate. Keep this overlay visibly separate from actual model geometry when the avatar is turned away from front.
- [x] **Limitations and confidence** — Clearly explain that the result is a visual approximation and does not model fabric drape, stretch, depth, complete body shape, tailoring, comfort, or guaranteed real-world fit. Communicate the available measurement/confidence status honestly.
- [x] **Compare and restart** — Provide a before/after comparison and an option to restart with different measurements or another dress image.
